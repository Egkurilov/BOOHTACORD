# Предлагаемые улучшения — аккаунт, переписка и навигация

Все пункты здесь — **кандидаты**, не обязательные релизные гейты. Приоритеты P1/P2 взяты из приложенного функционального аудита; размер `S/M/L` — относительный. Текущий продуктовый контракт и ACL из [AGENTS.md](../../AGENTS.md) обязательны. Пересечение IMP-13 уже учтено в [FE-53…55](../FRONTEND_TODO.md), поэтому второй карточки нет. Read-only архив IMP-05 требует решения и находится в [решениях](OPS_TODO.md).

### IMP-01 · P1 · L — свои сеансы и адресный отзыв
- [ ] Добавить caller-only список активных сеансов с непривилегированным ID, меткой, created/last-active и отметкой текущего; endpoint отзыва выбранного/всех остальных сеансов с CSRF/Origin, блокировкой старых cookie/WS и отзывом session-bound voice lease. Проверить два клиента, чужой session ID, старые API/SDK credentials и сохранность сеанса инициатора. **Зависимость:** QA-10, новый OpenAPI/mobile контракт; без IP/fingerprint/token в ответе.

### IMP-02 · P1 · S — понятный вход и reset без почты
- [ ] Сохранить фактический `register→login` в [AuthenticationLanding.vue](../../clients/web/src/identity/AuthenticationLanding.vue); добавить ясное подтверждение автоматического входа/ошибки второго шага, объяснение выдачи reset-ссылки администратором, 429 `Retry-After` и доступный show-password. Проверить used/expired link, focus, отсутствие автоповтора 429 и неизменность Unicode-пароля; `autocomplete` уже реализован.

### IMP-03 · P2 · M — актуализация имени и аватара
- [ ] Измерить текущую задержку member refresh; затем добавить metadata-only profile revision/invalidation и объединение повторных lookup. Проверить переименование B в сообщении, reply, поиске, roster и карточке A без reload, защиту от позднего старого ответа и очистку защищённых avatar object URL на logout. **Зависимость:** realtime schema и Flutter parity; не делать публичный avatar URL.

### IMP-04 · P2 · M — локальные избранные и сворачивание
- [ ] Добавить account+origin избранные каналы, локальное состояние свёрнутых категорий и быстрый поиск канала без изменения server topology revision. Проверить архивирование, пустые категории, доступность voice dock при свёрнутой категории и переход в экран без неявного voice transfer. **Граница:** одна гильдия, без персональных серверных ACL.

### IMP-06 · P1 · M — последствия admin-конфликта и закрытия VOICE
- [ ] В admin UI показать сравнение «было/теперь/ваше изменение» после 409 для имени, роли и порядка без слепого повтора; закрытие VOICE отображать как admission закрыт → SFU revoke pending → room empty → завершено. Два администратора не перетирают правки; ошибка SFU не выдаётся за success, повтор не создаёт лишний audit. **Зависимость:** DES-03 и QA-10.

### IMP-07 · P1 · M — черновики по беседам
- [ ] **Source готов, browser-приёмка открыта.** Memory-only per-account/per-conversation DraftStore сохраняет текст, reply, mentions и подготовленные upload IDs с generation guard; A→B→A возвращает черновик, поздний ответ A не меняет B. Успешный send очищает только отправленную версию, logout/account switch очищает всё. Проверить в двух настоящих вкладках TEXT/DM, upload pending и 507/retry; хранение DM-текста после перезапуска — отдельное privacy-решение.

### IMP-08 · P1 · L — первая непрочитанная запись
- [ ] **Частично:** caller-only `first_unread_message_id` добавлен в TEXT topology и DM navigation, веб показывает действие «К первому непрочитанному» и не продвигает курсор, пока пользователь не выбрал переход к последним. Доделать полноценную прокрутку с разделителем «Новые сообщения», forward-пагинацией для 100+ непрочитанных и восстановлением локального anchor+offset. Проверить удалённый anchor, свои сообщения, background tab и search hit без списания невидимого хвоста на PostgreSQL и в браузере. Это не read receipt собеседника.

### IMP-09 · P1 · M — единый переход к сообщению
- [ ] Переиспользовать существующий search-context путь для reply, search и будущей ссылки по resource IDs; открыть старую страницу по `at`, подсветить hit и вернуться к исходному scroll anchor. Проверить tombstone, недоступный DM без раскрытия имени, сохранение voice lease и keyboard focus. **Граница:** URL не даёт право чтения; перед кодом проверить уже подключённый reply-jump.

### IMP-10 · P1 · M — неопределённые отправки
- [ ] Поверх существующего exact-payload retry показать «Отправляем/Проверяем доставку/Не отправлено» и локальный список по беседам. После timeout сначала сверить сервер по `client_message_id`, затем повторять **тем же** UUID; изменённый payload получает новый UUID. Проверить потерянный response, явные 400/403, 507 upload и удаление optimistic row без ложного server delete. **Зависимость:** IMP-07.

### IMP-11 · P2 · L — @-ввод и личные упоминания
- [ ] Открывать существующий ID-picker при `@` с фильтрацией/keyboard/IME guards; отдельно спроектировать caller-only inbox упоминаний с точным переходом к сообщению. Проверить rename/edit/delete и чужой DM; не вводить `@everyone`, read receipt или текст DM в уведомление. **Зависимость:** IMP-09 и новый search/read контракт только для inbox.

### IMP-12 · P1 · M — настройки уведомлений по беседе
- [ ] Расширить нынешний глобальный on/off режимами «все/упоминания/без» для TEXT/DM, временной паузой и отдельным звуком начала стрима. Применять фильтр до захвата event ID; проверить две вкладки, delayed Web Lock, logout/account switch, mute канала без изменения unread и возврат после паузы. **Зависимость:** QA-03/05; без background push и без permission prompt при старте.

### IMP-14 · P1 · L — управляемая очередь upload
- [ ] Свести подготовку, progress, per-file retry, cancel и drag-and-drop активного composer в одну ограниченную очередь; успешные IDs не загружать повторно. Проверить третий failed файл, abort/reservation, A→B переключение, 10×25 MB и Send при pending/failed. **Зависимость:** FE-53…55, IMP-07, QA-05/08; UNATTACHED не удалять вымышленным клиентским DELETE.

### IMP-15 · P2 · L — файлы беседы

Удалённый message сразу исключается; DM metadata доступны только паре, preview/download повторно проверяют ACL. **Зависимость:** IMP-09 и FE-53; без OCR, публичного object store и индекса содержимого.

### IMP-16 · P2 · L — фильтры текущего поиска

### IMP-17 · P2 · M — качество русского поиска

Менять индекс только при измеренном выигрыше без потери точных ников и privacy. **Результат:** опубликованные query→expected IDs и ресурсный бюджет; дефект runtime заранее не утверждать.
