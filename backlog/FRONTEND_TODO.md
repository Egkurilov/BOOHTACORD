# Фронтенд — только открытые задачи

- [ ] **FE-63 · P1 · T-022/051 — Реальная RNNoise-приёмка и audio-engine parity.** Новая opt-in обработка микрофона добавлена в web и Flutter; ADR-014 намеренно оставляет RNNoise недоступным на macOS/iOS из-за связки VPIO AEC/NS, сохраняя стандартный engine. Flutter Windows CI #14 выявил несовместимость upstream VLA с MSVC; commit `b81128b` добавил CMake-генерируемые compiler-only overlays для Windows, сохраняя upstream source/model и их SHA-256 нетронутыми. Новый hosted Windows build и реальное CMake/PCM parity выполнение ещё не подтверждены — [MSVC overlay evidence](../evidence/noise-suppression/2026-10-02-windows-msvc-overlay.md). Дальше проверить на физических Windows и Android устройствах выбор `off/browser/rnnoise`, фактический engine после обработки кадров, сохранение предпочтения, mute/PTT/deafen, замену устройства, reconnect и bounded fallback при неподдерживаемом формате/ошибке. Для macOS проверить понятное сообщение `platform-aec-ns-coupled` и сохранение AEC. Затем провести согласованное прослушивание русской речи/шума, double-talk, маршрутов USB/Bluetooth и длительного звонка; фиксировать только агрегаты и hardware/build evidence, не PCM. Физическая/акустическая приёмка и release readiness остаются `NOT_RUN`/`NO_GO` — [ADR-014](../docs/adr/ADR-014-client-rnnoise.md), [acceptance matrix](../evidence/noise-suppression/2026-10-02-automated-gates.md).
- [ ] **FE-66 · P1 · T-022/051 — Мобильный Push-to-Talk без клавиатуры.** Android/iOS теперь включают PTT без назначения hardware key и используют удержание микрофонной кнопки в компактной voice dock; отпускание/отмена pointer и уничтожение dock глушат микрофон. Desktop сохраняет клавиатурный PTT. Unit/widget regressions и `flutter analyze` прошли — [QA-213](../evidence/flutter/qa213-mobile-push-to-talk-touch-2026-10-02-001.json). Проверить на физическом Android/iOS удержание, отпускание, прерывание звонка/системный жест, сворачивание и TalkBack/VoiceOver; проверить отсутствие передачи после любого отменённого жеста.
- [x] **FE-62 · P1 · T-054/060 — Восстановить CI после обновления версии приложения.** Устаревшее hardcoded ожидание заменено проверкой относительно `appVersionName`/`appBuildNumber` в `profile_screen_test.dart` (`2372460`); focused и полный Flutter suite прошли (404 теста), а последующий [CI #123](https://github.com/Egkurilov/BOOHTACORD/actions/runs/36991935255) завершился успешно. Исходный [CI #119](https://github.com/Egkurilov/BOOHTACORD/actions/runs/36989324807) был одним дефектом assertion в двух jobs.
- [ ] **FE-61 · P1 · T-030 — Обнаружение чужого стрима на macOS.** Исправлен фильтр, скрывавший активную публикацию без подписанного видеотрека (`autoSubscribe=false`): карточка, навигация и список экранов теперь используют незаглушённую screen-share публикацию. Открытие сохраняет явную подписку и показывает подключение до получения трека. Flutter повторяет web-состояние «Получаем первый кадр демонстрации…» до первого кадра — [QA-205](../evidence/flutter/qa205-flutter-screen-viewer-first-frame-state-2026-10-02-001.json). `didFirstFrameRendered` macOS/Darwin теперь означает upload pixel buffer в Flutter texture — [QA-206](../evidence/flutter/qa206-macos-texture-first-frame-upload-2026-10-02-001.json). Новый пользовательский симптом: browser-visible stream становится чёрным после переключения на Flutter macOS. Source review нашёл pending-frame gate, переживавший замену `VideoTrack`; тест падал до сброса флага, все 20 package tests и macOS Debug build проходят — [QA-209](../evidence/flutter/qa209-macos-renderer-track-replacement-2026-10-02-001.json). Также callback first-frame теперь scoped к текущему track generation, так что stale callback не снимает overlay у нового источника — test-first regression, suite 409 tests, macOS+Android Debug builds pass — [QA-210](../evidence/flutter/qa210-flutter-stale-screen-frame-callback-2026-10-02-001.json). Нативная гонка queued first-frame старого трека исправлена в обеих реализациях — [QA-211](../evidence/flutter/qa211-macos-renderer-track-generation-2026-10-02-001.json). Дополнительный test-first regression обнаружил асинхронный ответ `srcObject = null`, который после attach нового потока сбрасывал его размеры/`renderVideo`; ответы Dart renderer теперь scoped к generation источника, включая dispose. Все 22 package tests, 413 client tests, analyzer и macOS Debug build проходят — [QA-214](../evidence/flutter/qa214-native-video-renderer-source-generation-2026-10-02-001.json). Причинность чёрного экрана и реальные decoded/displayed frames не подтверждены; live-проверка публикации, подписки, отображённых кадров и unpublish на Mac остаётся открытой. Регрессия discovery воспроизведена тестом до исправления — [QA-201](../evidence/flutter/qa201-macos-unsubscribed-screen-discovery-2026-10-01-001.json). Pixel-снимок в момент проверки не содержал активного MediaProjection — [QA-204](../evidence/flutter/qa204-pixel-readonly-stream-state-2026-10-02-001.json).
