## Work completed

- Added the Web/Flutter Design V2 token crosswalk and opaque token-pair contrast measurements in [`docs/design/DESIGN_V2_TOKEN_CROSSWALK.md`](../../docs/design/DESIGN_V2_TOKEN_CROSSWALK.md). Updated [`docs/design/GUILDCHAT_V1_STATUS.md`](../../docs/design/GUILDCHAT_V1_STATUS.md) to distinguish current runtime tokens from the historical GuildChat v1.0 snapshot.
- Continued #290 by migrating canonical token color literals to semantic CSS variables in the admin-member, authentication, mobile-navigation, member-popover, screen-viewer and voice-room presentation styles. Added `design_token_usage.spec.ts` to prevent those styles from reintroducing exact copies of canonical palette values, and updated two focused contract assertions to check token roles.
- Reviewed the 16 child issue scopes against the current client/test tree and existing Design V2 evidence. No screenshot-driven runtime defect was asserted without a reproducible runtime sample.
- The #290 CSS migration preserves the exact token values, so it changes token ownership without changing rendered colors. The #292 history integration changes navigation state only; no API, ACL, session, or media contract changed.
- A new Chrome regression for #298 exposed that the Web destructive-confirmation dialog did not wrap keyboard focus from its last control. Added an explicit Tab/Shift+Tab loop; Cancel remains the initial/default action and focus returns to the trigger after cancel.
- The #300 screen-share setup dialog had the same native-dialog focus-wrap gap. Extracted a shared modal Tab helper and verified forward/reverse boundary wrapping in both production dialogs.
- A readiness-panel browser regression for #299 exposed that initial loading was announced as “Нет свежего подтверждения готовности” and refresh kept announcing the previous ready state. The panel now announces initial checking separately and explicitly identifies the previous sample while a refresh is pending.
- A #296/#299 browser check exposed that media diagnostics announced “Нет данных” during its first request and left the refresh button unchanged. It now reports load/reload progress in the live status and button, retains the prior response while checking, clears an old alert at retry start, and exposes a new 503 failure accurately.
- The #295 320 px admin-shell check confirmed that all seven section buttons were only reachable by horizontal scrolling, with no visible cue. Added a mobile/tablet instruction and linked it as the navigation description; each section now scrolls into view without widening the page.
- The wider #295 shell regression exposed a second duplicate “Администрирование” heading on the Members section; the shared workspace header already carries that context. Removed the members-only visible heading exception while retaining the accessible panel heading and visible section heading.
- The #295 inventory confirmed that `WorkspaceApp` owns guild identity and panel state, `SettingsWorkspaceHeader` owns the admin context and close action, `AdminPanel` owns seven section controls, and `WorkspaceMain` swaps the panel content while retaining the conversation pane. Admin section selection now lives in `WorkspaceApp` and survives unmount/reopen.
- Because the admin panel heading is intentionally visually hidden, its initial focus now lands on the selected, visible section button; the hidden H1 continues to label the admin region for assistive technology.
- Flutter #295 checks found horizontal section tabs had no visual scroll cue; added the same instruction below the tabs and as the tab-bar semantics hint on compact screens. At 320 px with 2× text the readiness header also overflowed by 23 px; its refresh action now stacks below the heading on compact layouts.
- Added #294 browser fixtures at 320/390 px. Runtime checks confirmed the Web empty-DM state had no visible next action and the conversation search control was hidden on phone widths. The empty state now offers a visible “Начать диалог” CTA; mobile search is visible with a measured 44×44 px target and retains query/results per DM through result-context return, closing/reopening search, and switching to another DM and back.
- Added #297 form-state coverage for dirty profile edits across tabs, pending/save failure/retry/success feedback, and clearing stale state after edits. Profile-name, avatar, and password mutations announce their pending action; busy forms prevent edits racing an in-flight save.
- #297 now protects dirty profile/password drafts when workspace navigation leaves the settings panel. Logout and individual/bulk session revocation require an explicit `AdminConfirmation`; session contracts and server APIs are unchanged.
