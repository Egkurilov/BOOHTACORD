## Цель

Сделать self-hosted веб-платформу одной гильдии: участник открывает адрес сервера, входит, подключается к голосовому каналу, разговаривает, показывает игру со звуком либо смотрит демонстрацию другого участника. Приоритет: голос, демонстрация и звук игры, восстановление связи, чат, администрирование.

## Важное о границах и доказательствах

- В рабочей папке отсутствуют упомянутые ТЗ `contracts/`, `backlog/`, `docs/`, `templates/` и правила проекта. До начала реализации их нужно добавить или получить от владельца и сверить с этим ТЗ; расхождения фиксировать ADR и тестом.
- Нельзя подменять неизвестные предположениями: поддержанные версии Chrome/ОС, возможность захвата игры со звуком, прекращение медиа по отзыву доступа и достаточность VM подтверждаются POC, измерениями и ADR.
- В первую версию не входят: multi-guild, глобальные друзья/DM, закрытые каналы и ACL на канал, камера, запись/транскрибация, групповые DM и звонки, email/OAuth/инвайты, боты/webhooks, Kubernetes/HA, бэкапы/репликация, mobile и обязательная поддержка Safari/Firefox/Linux.
- Один deployment обслуживает одну изолированную гильдию; сервер не создаёт бэкапы БД или вложений и не удаляет опубликованную историю для освобождения места.

- [ ] **T-041 · Личные диалоги (REQ-DM-01).** Готовы migration и unit-tested authenticated `POST /direct-messages`: только два разных active account образуют canonical UUID-пару с DB unique constraint и atomic upsert, поэтому concurrent запросы не создают дубликат. `GET /direct-messages` возвращает только canonical pairs, содержащие caller, и display name другого участника без role input или `blocked_at` filter, сохраняя навигацию к retained history после ban. `POST /direct-messages/{id}/messages` создаёт author-and-DM-scoped idempotent сообщение только когда caller входит в пару и оба account не blocked; predicate выполнен с insert в одном SQL statement. Для PNG/JPEG/GIF отдельный protected route после той же ACL‑проверки проверяет размеры, ограничивает 16 777 216 source pixels, нормализует первый raster frame в bounded PNG preview (длинная сторона ≤1024) и отдаёт его с `no-store`; UI скрывает preview по защищённой 404-ошибке. SVG/HTML и другие source files остаются forced download, без object URL или public file path. Остаются DM-вложения, authenticated browser e2e, unlink/physical collection с проверкой живых ссылок и аудитом.
- [ ] **T-046 · Нехватка места и техническая очистка (REQ-STORAGE-03).** Готовы атомарное резервирование места конкурентным загрузкам до/во время записи, `INSUFFICIENT_STORAGE` и cleanup незавершённого файла при ошибке upload. Добавлен отдельно тестируемый filesystem primitive для cleanup только direct `staging/upload-*.part` старше часа: он не рекурсирует, не следует symlink, не удаляет unexpected names и пока не запускается в production. Подготовлена repeatable migration с partial index только `UNATTACHED` records по `created_at, storage_key` для будущего bounded cleanup scan. Остаются operator/schedule invocation, транзакционно подтверждённая и audit‑зафиксированная cleanup `UNATTACHED` objects старше суток, а также запрет физического удаления при любой живой ссылке; опубликованная история никогда не удаляется по TTL или ради места.
- [ ] **T-047 · Тесты приватности чата и файлов.** Негативными тестами закрыть утечки DM и вложений через history, search, reply, event replay, notification preview, counters и admin endpoints; проверить idempotency, race conditions и ограничения upload.

## P6 — интеграция и release gate

- [ ] **T-060 · Контрактные, unit, integration и E2E-тесты.** Проверить REST/WS контракты, миграции, транзакционные гонки, ACL, безопасность, auth/admin/channel/voice/screen/chat/DM/search/upload сценарии.
