# UI/UX 2026 state matrix

This matrix records implemented states and the tests that currently exercise them for epic [#289](https://github.com/Egkurilov/BOOHTACORD/issues/289), especially [#296](https://github.com/Egkurilov/BOOHTACORD/issues/296) and [#299](https://github.com/Egkurilov/BOOHTACORD/issues/299). It describes client presentation only; it does not change API, ACL, session, or media contracts.

`Covered` means a deterministic test exercises the named UI state. `Partial` means some states are covered but a full response/input/accessibility matrix is still missing. `NOT_RUN` remains the status for physical-device or assistive-technology acceptance that has not taken place.

## Cross-cutting rules

- Empty, stale, forbidden, offline and unavailable are distinct states. A missing report or failed request is never converted into “no items”.
- A recoverable error can be retried explicitly; a denied request does not poll repeatedly. A repeated mutation is not automatic.
- Pending and completed outcomes use contextual live-region feedback. User-visible data such as messages, tokens, DM identifiers or attachment contents is not added to telemetry for these states.
- Keep the last known data visible only when it is labelled stale or explicitly retained during refresh; do not announce it as current after a failed refresh.
- Automated test status does not imply physical-device, VoiceOver, TalkBack, or real-SFU acceptance. Those gates remain separately recorded in [`UIUX_2026_RELEASE_GATE.md`](UIUX_2026_RELEASE_GATE.md) and the [epic evidence](../../evidence/qa/uiux-2026-epic-289-2026-10-09.md).
