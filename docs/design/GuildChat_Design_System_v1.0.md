# GuildChat — дизайн-система для агентной реализации

**Версия 1.0.0 · 19 сентября 2026 · Проект: Self-hosted Voice & Screen Sharing Platform**

> Сохранённая исходная документация, полученная от владельца проекта. Она определяет визуальный контракт; при конфликте с утверждённым ТЗ Voice Platform приоритет остаётся за ТЗ. Статус внедрения и проверяемые результаты находятся в [GUILDCHAT_V1_STATUS.md](GUILDCHAT_V1_STATUS.md).

## 1. Назначение

Этот пакет переводит два приложенных скриншота в конкретный контракт интерфейса: цвета, размеры, типографику, компоненты, состояния, взаимодействия и приёмку. Агент получает не пожелание «сделай похоже», а значения и проверяемые сценарии.

Основной стиль — тёмный скриншот. Светлый board используется как образец согласованной библиотеки компонентов; светлая палитра сохранена только для справки. В первой версии продукта остаётся тёмная тема без переключателя. Рабочее имя GuildChat взято с board, но не утверждает окончательный бренд.

**Это дизайн-пакет, не готовое приложение.** Есть автономный интерактивный HTML-референс, CSS-токены и типы представления, но нет реализации Vue-функциональности, сервера или медиаслоя. Техническое задание проекта продолжает действовать.

## 2. Источники и приоритет

`references/01-dark.png` и `references/02-light-board.png` — оригиналы без редактирования. `references/TZ_Voice_Platform_v1.0.md` — согласованная продуктовая основа. Новая геометрия, токены, недостающие экраны и точная семантика состояний обозначены **D — проектное решение**, а не выданы за детали, которые уже были на скриншотах.

Функциональные требования пользователя выше визуальных намёков. Новый дизайн заменяет только конфликтующие прежние инженерные цвета/размеры UI_SPEC; API, приватность, медиаархитектуру и критерии реального качества он не отменяет. Визуальный источник точных значений — JSON-токены и контракты; HTML показывает часть их применения. Противоречие между нормативными документами нужно исправить согласованно, а не выбирать удобную сторону.

Подробная таблица решений и отличий — `docs/01_SOURCE_AND_SCOPE.md`.

## 3. Визуальный характер

Три спокойные области: навигация, основное содержимое, участники. Тонкие разделители, нейтральная подсветка выбранного канала, круглые аватары, линейная переписка без пузырей. Большая свободная область при короткой истории — нормальное состояние, не повод заполнять экран декоративными карточками.

Снизу слева постоянно доступны голос и профиль. В центре — текстовый канал, личная переписка, голосовая комната или выбранная демонстрация. Стрим получает основную площадь, без обрезки и растягивания изображения. Палитра спокойная; акцент используется для действия и фокуса, а не для заливки каждой панели.

Не переносить дымку/шум растрового референса как blur всей страницы. Не добавлять стеклянные панели, неоновые рамки, большие градиенты, маркетинговые KPI и колонку выбора серверов.

## 8. Ключевые сценарии и инварианты

**Голос не привязан к открытому экрану.** Навигация в чат, DM, профиль или администрирование сохраняет комнату, mute/deafen и собственный screen share. Открытый канал и подключённый голосовой канал визуально различаются. Сбой backend WebSocket не равен потере исправного медиа.

**Mic и deafen — разные управления.** Mute не отключает игровой звук собственной демонстрации. Deafen выключает удалённый звук и передачу микрофона, но собственная демонстрация может продолжаться; UI предупреждает об этом. После снятия deafen восстанавливается предыдущий выбор mute. Нельзя автоматически включить микрофон, который пользователь выключил.

**Один удалённый viewer.** Переключение источника сначала прекращает старые видео/игровой звук, затем включает новые. Другие источники показаны метаданными, не скрытыми видеопотоками. Завершившийся стрим не заменяется автоматически чужим звуком.

**Уход из viewer [D].** Переход к чату/DM/settings останавливает удалённый просмотр и его игровой звук, сохраняя голос и собственную публикацию. Обратный переход не включает чужой звук сам. Это дополнительная определённая политика навигации; она отсутствовала в референсах и не выдаётся за прямой ответ владельца.

**Правдивое качество.** Выбранный режим1080p/60 — целевой. Фактические resolution/FPS/bitrate берутся из свежих измерений; до них показывается «Нет данных». Автоадаптация снижает качество экрана ради голоса и объясняет изменение. Наличие аудиодорожки не доказывает слышимость игры или отсутствие эха.

**Ошибки не объединены в один красный toast.** Отмена системного picker — нормальная отмена. Нет разрешения, нет audio track, окно закрыто, сеть потеряна, стрим завершён, место закончилось — разные состояния с конкретными действиями. Kick/ban/logout не запускают бесконечный reconnect.

**Приватность переписки.** DM1:1, без звонков/камеры/групп. Счётчик непрочитанного — не read receipt собеседника. Admin не видит чужие DM через интерфейс; серверные ACL остаются обязательными. Файл до25МБ, без удаления старой истории при недостатке места.

## 9. Доступность и тексты

Видимый focus, подпись каждого icon button, управление меню/диалогами клавиатурой, возврат фокуса, отсутствие вложенных кнопок и воспроизводимость действий без right click обязательны. Говорящий обозначается не одним зелёным цветом; mute — не только красной заливкой. Значимые ошибки остаются видимыми, а не исчезают до прочтения.

Для активного обычного текста принят порог контраста4,5:1, для нужных контуров/control indicators —3:1. Это критерии проекта и расчёт выбранных пар, не сертификация полного интерфейса. Неактивные элементы, динамическое видео, пользовательские изображения и все возможные наложения не покрыты одним расчётом палитры.

Полные правила и тексты — `docs/07_ACCESSIBILITY_AND_COPY.md`. PTT активной страницы сбрасывается при потере фокуса; глобальные сочетания во время игры не вводятся.

## 10. Внедрение и готовность

Передать агенту **весь архив**; стартовая инструкция — `START_AGENT.md`. Рекомендуемое размещение: `docs/design/guildchat-v1/`. Не заменять корневой AGENTS.md и не переписывать приложение HTML-демонстрацией.

`tasks/tasks.json` содержит12 задач с зависимостями. `contracts/acceptance.json` —46 проверок, исходно NOT_RUN. Реализация закрывается через код, состояния, автоматический тест, визуальный baseline и evidence. Пример формы: `templates/implementation-evidence.json`.

Нет необходимости читать все JSON заново для каждого изменения: после аудита агент выбирает C/S/DS-A текущей задачи. Но отсутствие компонента в HTML-showcase не исключает его из обязательного контракта.

## 11. Что можно посмотреть и что проверено

`preview/index.html` — автономный HTML/CSS/JS reference с8 демонстрационными экранами, выбранными состояниями, локальными действиями и справочной светлой палитрой. Не обращается к сети и не запрашивает микрофон. Фиктивный stream canvas и значения метрик явно помечены как демонстрационные.

В пакете проверяются: структура и ссылки контрактов, токены, типы представления, расчёт контраста, локальный рендер/действия HTML. В `qa/` сохранены результаты и12 рендеров. Отдельно зафиксированы границы среды: headless Chromium на Linux с загрузкой разметки в страницу; прямое открытие file:// было недоступно из-за политики среды.

**Не проверены:** внедрение Vue, полный набор66 состояний в приложении, Windows/macOS Chrome, реальный browser zoom, screen reader, game capture/audio, API/ACL,100-пользовательская нагрузка и production deployment. Ни одна из46 проверок приложения не объявляется пройденной только на основании этого дизайна.
