# ADR-013: превью демонстрации экрана в карточках участников

Статус: принято по запросу владельца продукта, 2026-10-01.

## Контекст

Web и Flutter отправляли миниатюры экрана через LiveKit DataPackets. Эти
пакеты не доставляются при текущем credential: `CanPublishData=false`.
Локальное завершение `publishData` не подтверждает доставку. Включение
`CanPublishData` разрешило бы каждому участнику комнаты отправлять произвольные
DataPackets всем участникам; сервер не ограничивает их topic или размером,
которые проверяются только в клиентах. Такое расширение прав публикации не
приемлемо для исправления одной UI-функции.

## Решение

- Сохранить `CanPublishData=false`. Не добавлять исключение для thumbnail topic
  и не ослаблять LiveKit room grant.
- Не использовать успешное завершение локальной отправки DataPacket как
  признак того, что превью было доставлено.
- Исследовать превью как локальный захват кадра уже опубликованной
  LiveKit screen-share видеодорожки, доступной участникам этой голосовой
  комнаты. Захват может использовать только тот же серверно авторизованный
  scope, что и просмотр демонстрации; Go не ретранслирует медиаданные.
- Если реализация использует временную подписку ради кадра, ограничить её
  одной дорожкой активной демонстрации и коротким deadline; после первого
  пригодного кадра немедленно отписаться. При отсутствии кадра или ошибке
  оставить аватар. Не создавать постоянную подписку для скрытых превью и не
  мешать явному просмотру, который остаётся единственным режимом длительной
  подписки. Точный механизм и deadline должны быть подтверждены тестами SDK и
  платформ, прежде чем закрывать задачу.
- Превью остаются краткоживущими UI-данными: без хранения, записи или отдельной
  передачи за пределы участников комнаты.

## Последствия и проверка

Подписка на видеодорожку может кратковременно потреблять сетевой трафик и
декодирование на участниках комнаты. Нужно проверить порядок track publish /
subscribe / unsubscribe, что превью не вытесняет выбранный просмотр, а
отписка происходит при остановке трансляции, выходе из комнаты и смене
публикации. Покрыть поведение тестами web и Flutter и подтвердить его парным
live-тестом Android → macOS/web. До этих проверок кросс-клиентское превью
остаётся открытым пунктом; безопасность не подтверждается только клиентскими
лимитами.

Проверить, что credential и регрессионный тест по-прежнему запрещают
`CanPublishData`, а в web и Flutter нет используемого thumbnail DataPacket
пути. Не закрывать пункт без evidence на жизненный цикл подписки и парной
приёмки.
